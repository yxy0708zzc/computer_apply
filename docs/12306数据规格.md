# 12306 数据规格处理指南

> 本文档描述 tripai 系统中全部 12306 接口的返回数据规格、解析规则与已知坑。
> 处理代码位置：`collect/`（离线建库采集）、`app/online.py`（实时余票/票价）、`app/database.py`（入库 schema）。
> 所有结论均来自 2026-10 实测抓包核验，非文档转述。

---

## 0. 接口总览

| # | 接口 | URL | 用途 | 采集位置 |
|---|---|---|---|---|
| 1 | station_name.js | `kyfw.12306.cn/otn/resources/js/framework/station_name.js` | 全国车站名录 | `collect/stations.py` |

## 1. 车站表 station_name.js

**原始形态**：一个 JS 文件，单行 `var station_names='@...@...';`

**格式**：以 `@` 分隔条目，每条以 `|` 切 6 列：

```
@bjb|北京北|VAP|beijingbei|bjb|0
 ①简拼 ②站名 ③电报码 ④全拼 ⑤首字母 ⑥序号
```

**入库映射**：`stations(station_id=③电报码, station_name=②站名)`

**要点**：
- 全国共 **3404 条**（2026-10 实测）
- 电报码即全系统通用的"车站 ID"（queryZ/queryByTrainNo/queryAllPublicPrice 的站参数都用它）
- 解析用 `INSERT OR IGNORE`，重复执行安全

## 2. 车次发现 train/search

**请求**：`GET ?keyword={前缀}&date={YYYYMMDD当天}`
- keyword 为车次前缀：字母（K/G/C/T/Z/D）或纯数字
- **单次返回上限 200 条，无分页**——超密前缀会被截断

**返回 JSON**：
```json
{"status": true, "data": [
  {"station_train_code": "G531", "train_no": "240000G53106", ...},
  ...
]}
```

**发现策略**（避免 200 截断）：
- 每字母按两位数前缀 `{L}10`~`{L}99` 逐条查（每前缀 <200 条完整）
- 个位 `{L}1`~`{L}9` 补精确车次
- 某前缀仍达 200 → 递归三位数子前缀（安全网）
- 纯数字车次（1461 等）同法（过滤掉字母车次）

**入库映射**：`trains(train_num=station_train_code, train_no=train_no)`

**要点/坑**：
- **同向改号车**：同一物理列车前后半段有两个显示码、共享同一 `train_no`（如 G2082/G2083）。tripai schema 的 `train_no UNIQUE` 只保留一码，其余跳过并计数（实测 G 字头跳过 1520 个）
- search API 按 `date=当天` 查询，返回的是当前运行图

## 3. 经停 queryByTrainNo

**请求**：`GET ?train_no={train_no}&from_station_telecode=BJP&to_station_telecode=SHH&depart_date={YYYY-MM-DD}`
- telecode 参数是**占位符**（BJP/SHH 固定即可），返回的是全线经停
- `depart_date` 必须是该车的**实际开行日**——非每日车在不开行的日期返回**空列表**（不是报错）

**返回 JSON**：
```json
{"status": true, "data": {"data": [
  {"station_no": "01", "station_name": "北京南",
   "arrive_time": "----", "start_time": "17:00", "depart_time": "17:00",
   "stop_duration": "----", "station_train_code": "G1",
   "train_class_name": "高速", "isEnabled": false},
  ...
]}}
```

**字段事实（普速/高速差异）**：

| 车型 | 发车时刻字段 | 到达时刻字段 | 停站时长字段 |
|---|---|---|---|
| 高速/动车（G/D/C） | `depart_time` | `arrive_time` | `stop_duration`（"6分钟"） |
| 普速（K/T/Z） | `start_time` | `arrive_time` | `stopover_time` |
| 始发站 | `arrive_time = "----"`（占位） | 同左 | — |

**占位符**：无值时为 `"----"`（四个减号），**不是** null 或空串。

**入库映射**（tripai schema 只存发车时刻一个时间）：
`train_stops(stop_time = depart_time ?? start_time，经 `_norm_time` 校验 HH:MM 后入库，脏值存空串)`

**已知坑**：
- **非每日开行车**：候选日期必须多日兜底（tripai 用 +0/+1/+2/+3/+9/+13），否则大面积"无经停"假象
- `station_no` 是 12306 原始站序（字符串，如 "01"），入库转 int 作 `stop_no`

## 4. 余票 queryZ（★ 最复杂）

**请求**：`GET ?leftTicketDTO.train_date={YYYY-MM-DD}&leftTicketDTO.from_station={电报码}&leftTicketDTO.to_station={电报码}&purpose_codes=ADULT`

**返回 JSON**：
```json
{"status": true, "data": {"result": [
  "预订|JL8vK1P7...|240000G53106|G531|VNP|AOH|VNP|AOH|06:08|12:04|05:56|Y|...|有|...|6|无|...",
  ...
]}}
```
`data.data.result` 为字符串数组，**每条以 `|` 分隔 35+ 字段**。无车次时 `data` 为 `null`（status 仍 true）——必须 `(data.get("data") or {}).get("result", [])` 兜底。

### 4.1 字段位表（实测核验）

| 索引 | 含义 | 示例 |
|---|---|---|
| [2] | train_no（12306 内部号） | 240000G53106 |
| [3] | 显示车次码 | G531 |
| [4]/[5] | 出发/到达电报码 | VNP / AOH |
| [8] / [9] | 出发 / 到达时刻 | 06:08 / 12:04 |
| [10] | 历时 | 05:56 |
| [26] | **无座** | 有/无/数字/候补 |
| [28] | **硬卧/二等卧** | 同上 |
| [29] | **硬座** | 同上 |
| [30] | **二等座/二等包座** | 同上 |
| [31] | **一等座** | 同上 |
| [32] | **商务座/特等座** | 同上 |
| [33] | **动卧** | 同上 |
| [24] | **软座** | 同上 |
| [23] | **软卧/一等卧** | 同上 |
| [21] | **高级软卧** | 同上 |
| [20] | **优选一等座**（新席位，智能动车组） | 数字（如 4）/ 无 |

### 4.2 席别列的三个事实（用户截图确认）

1. **每两三名共用一个数值**：如"商务座/特等座"是一列一个值；"软卧/一等卧"（f23）与"动卧"（f33）在页面上是同一列的两个数据源（Z/T 车走 f23、D 车走 f33）
2. **可能为空**：该车无此席时字段为空串/`--`，该席别列在页面不显示
3. 值域：`有`（充足）/ `无`（售罄）/ `候补` / 数字（剩余张数）/ `--`

**tripai 处理**（`online.py`）：
- `SEAT_FIELDS`：字段位 → **组合名**（如 `32 → "商务座/特等座"`），组合名即页面列名
- `SEAT_GROUPS`：同值组成员表——指定任一成员名（如"特等座"）可命中组合列
- `all_seats` 键 = 组合名，值 = 原文（有/无/数字/候补）；键缺失 = 该车无此席（与空值区分）
- 匹配：`_match_seat(seats, seat_type)`——精确键 → 组成员 → 反向组名

### 4.3 改号车匹配

queryZ 按区间返回的车次码可能是**同 train_no 的改号码**（查 G2082 段返回 G2083）。匹配顺序（`online.match_train`）：
1. 显示码相同 → 命中
2. **train_no 相同** → 命中（tripai 库 trains 表有 train_no，直接比对）

### 4.4 无座/空值的展示语义

| 原文 | 解释 | ticket_status | tickets 数值化 |
|---|---|---|---|
| 有 | 充足 | ok | 99 |
| 数字（如 6） | 剩余张数 | ok（≥人数）/ few（<人数） | n |
| 无 | 售罄 | none | 0 |
| 候补 | 需候补下单 | none | 0 |
| -- / 空 | 不发售 | unknown | None |

## 5. 票价 queryAllPublicPrice

**请求**：`GET ?leftTicketDTO.train_date={日期}&leftTicketDTO.from_station={电报码}&leftTicketDTO.to_station={电报码}&purpose_codes=ADULT`
Headers：`Referer: .../otn/view/queryPublicIndex.html` + `X-Requested-With: XMLHttpRequest`

**返回 JSON**：
```json
{"status": true, "data": [
  {"queryLeftNewDTO": {
     "station_train_code": "G1", "train_no": "240000G10I0",
     "train_class_name": "高速",
     "ze_price": "01390", "zy_price": "02220", "swz_price": "04850",
     ... }},
  ...
]}
```
`data` 为**该区间该日期所有开行车次**的列表（一次请求拿到全区间）。

### 5.1 票价字段 → 实际席别（字段驱动，实测核验）

| 接口字段 | 事实席别 | 实测值（G1 北京南→廊坊） |
|---|---|---|
| `ze_price` | 二等座/二等包座 | 01390 → **139.0 元** |
| `zy_price` | 一等座 | 02220 → 222.0 元 |
| `swz_price` | 商务座/特等座 | 04850 → 485.0 元 |
| `yz_price` | 硬座 | 00110 → 11.0 元（K1002 实测） |
| `yw_price` | 硬卧/二等卧 | 00650 → 65.0 元 |
| `rw_price` | 软卧/一等卧 | 00895 → 89.5 元 |

- **单位是"角"**：`float(值) / 10.0` = 元
- **字段驱动原则**：哪个字段有值就映射为该字段的事实席别。`train_class_name` 的值多变（"高速"/"动车"/"快速"/空），**不作映射依据**（实测 K1002 class="快速" 仅 yz/yw/rw 有值；盲用高速映射会把硬座标成二等座）
- 普速车 ze/zy/swz 天然为空 → 天然不会误标

### 5.2 日期维度（★ 关键坑）

票价列表**按日期返回当日开行车次**：
- 非每日车在不开行的日期**不在列表里**（G1108 今天开行但 +3 日期列表无它）
- 必须多日期兜底：tripai 统一候选 **+0/+1/+2/+3/+9/+13**（经停与票价两处一致）

### 5.3 爬取策略（travel2 同款）

- **相邻站对爬取**：每车 N-1 次请求（G1=6 次），非全排列
- **非相邻段离线累加**：A→C = A→B + B→C（各席别独立推算）→ 任意区间都有参考价
- **市内超短段不发售**：如 广州→广州白云 该段无票价数据 → 跳过该段继续（不放弃整趟），依赖该段的推算自动回避

**入库映射**：`prices(train_num, from_station_id, to_station_id, seat=实际席别名, price=元, crawl_date)`

## 6. 通用处理规则

### 6.1 反爬形态识别（`_is_anticrawl`）

| 形态 | 判定 |
|---|---|
| HTTP 403 / 429 | 反爬 |
| HTTP 200 + 响应体 < 1000 字符 + 含关键词（验证码/captcha/访问太频繁/触发风控…） | 反爬 |
| HTTP 200 但 body 是 HTML（XHTML 错误页，可能带 UTF-8 BOM） | 落入 JSON 解析异常分支处理 |

反爬处置：**换 UA + 重建会话 + 退避重试**（"换身份"而非久等）；余票接口另有全局串行锁 + 每 60 次主动换会话。

### 6.2 status 包裹

接口 2/3/4/5 成功响应均有 `"status": true` 外层；`status != true` 一律按失败重试。
注意接口 4 的 `data` 可为 `null`（无车次），接口 3 的 `data` 可能为非 dict——均需防御。

### 6.3 时刻占位符

`"----"`（四个减号）= 无值； trips 统一过 `_norm_time`（正则 `^\d{1,2}:\d{2}$`）后入库，脏值存空串，查询层再 GLOB 过滤。

### 6.4 日期维度

| 接口 | 日期参数 | 语义 |
|---|---|---|
| train/search | `date=YYYYMMDD`（当天） | 当前运行图 |
| queryByTrainNo | `depart_date`（必须开行日） | 该日全线经停 |
| queryZ / queryAllPublicPrice | `train_date`（预售期内） | 该日开行车次的余票/票价 |

**统一多日期兜底**：`+0/+1/+2/+3/+9/+13`（非每日车在单一日期会"消失"）。

## 7. 入库映射对照（12306 → tripai schema）

```
stations(station_id=电报码, station_name=站名)                       ← 接口1
trains(train_num=显示码, train_no=内部号)                            ← 接口2（同 train_no 多码取一）
train_stops(train_num, stop_no=station_no, station_id=电报码,
            station_name, stop_time=发车时刻)                        ← 接口3
station_trains(station_id, station_name, data=[{train_num, stop_time}] JSON)  ← 由 train_stops 重建
prices(train_num, from_station_id, to_station_id,
       seat=实际席别名, price=元, crawl_date)                        ← 接口5
```

实时余票（接口4）**不入库**，每次联网实时取（反爬限制 + 数据时效性）。

## 8. 已知坑清单（速查）

1. queryZ `data` 可为 `null`（无车次）——`or {}` 兜底
2. 时刻占位符是 `"----"`，空串与 `--` 语义不同（不发售 vs 无该席）
3. 经停接口：普速用 `start_time`、高速用 `depart_time`；占位符 `----` 出现在始发站 arrive
4. 非每日车在不开行日期"消失"（经停/票价同理）——多日期兜底 +0/+1/+2/+3/+9/+13
5. 同向改号车共享 train_no（发现阶段按码入库冲突需跳过；余票匹配按 train_no 兜底）
6. queryZ 席别列多名共用数值（组合名）且可为空——匹配走同值组，缺失与售罄是两种状态
7. 优选一等座是新席位，字段位 **f[20]**（老文档无此字段）
8. 票价单位是角（÷10 转元）；市内超短段无票价（跳段继续）
9. train_class_name 值多变（"快速"/空），席别判断只信字段值不信 class
10. queryZ 端点偶发返回 XHTML 错误页（带 BOM）——JSON 解析异常即重试 + 换会话，会自愈
11. 票价接口的 `data` 列表按日期返回**当日开行**车次——爬非每日车票价必须逐日轮换
12. queryAllPublicPrice 一次返回**全区间所有车次**——按车次过滤后再取价，天然可批量建库
